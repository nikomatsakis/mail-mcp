What this is, in plain words

An AI assistant has no mailbox. It cannot log in to yours, cannot see who wrote to you yesterday, and cannot send anything on your behalf. This is the bridge: a small program that runs on your own machine, holds your mail credentials, and gives the assistant a precise set of things it may do with them.

01

It runs on your computer

Started by your assistant, talking to your mail server directly. No account here, no service in the middle, nothing to sign up for.

02

You give it one address and one password

An app-specific password from your provider — the kind you can revoke on its own without touching your account.

03

The assistant gains 20 abilities

"What came in overnight", "reply to Anna", "show me the invoice she attached" — asked in normal words.

What you need before you start

  • A mailbox that speaks IMAP — which is nearly all of them. Gmail, Outlook, iCloud, Fastmail, Yandex and a dozen others are recognised from your address alone; anything else needs two host names you can copy from your provider's help page.
  • An app-specific password for that mailbox. Creating one takes a minute and is step 1 below.
  • An assistant that speaks MCP — Claude Code, Claude Desktop, Cursor and others.
  • Node.js 20 or newer, because the server runs on your machine.

Setup

Three steps, about two minutes

Create an app-specific password

Your normal password will not work: providers stopped accepting it for mail programs years ago. What you need instead is a separate password that exists only for this, and can be revoked without changing anything else.

ProviderWhere to click
Gmail / WorkspaceTurn on 2-Step Verification first, then myaccount.google.com/apppasswords. Workspace accounts also need IMAP enabled by an administrator
iCloudappleid.apple.com → Sign-In and Security → App-Specific Passwords. Your login is often just the part before @
FastmailSettings → Privacy & Security → App passwords
Yahoo / AOLAccount security → Generate app password
Yandex / Mail.ruSecurity settings → app passwords, and switch IMAP on under mail-client settings
ZohoSecurity → App passwords, plus IMAP access in Mail Settings
Outlook.com / Microsoft 365Usually OAuth only — see the note below
ProtonInstall Proton Bridge and use the login and password it shows you
Your company serverOften your normal password. Ask whoever runs it for the IMAP and SMTP host names
Microsoft is the awkward one. Personal accounts and most tenants now accept only OAuth, so no password will work. Supply an access token as the password together with MAIL_AUTH_TYPE=oauth2, or use a mailbox elsewhere. The same option works for Gmail if you prefer a token to an app password.

Install and connect

Once, in a terminal — the server is a small Node program that your assistant will start on its own from then on: 

git clone git@github.com:amalychev/mail-mcp.git
cd mail-mcp
npm install && npm run build

Then point your assistant at it. Pick the tool you use:

One command:

claude mcp add mail \
  --env MAIL_USER=you@fastmail.com \
  --env MAIL_PASSWORD=your-app-password \
  -- node /absolute/path/mail-mcp/dist/index.js

For a recognised provider that is the whole setup — the incoming and outgoing servers are derived from your address. For any other mailbox, add --env IMAP_HOST=… and --env SMTP_HOST=….

Prefer to write the configuration by hand? Create .mcp.json in the root of the repository you work in — everyone who opens it gets the same setup: 

{
  "mcpServers": {
    "mail": {
      "command": "node",
      "args": ["/absolute/path/mail-mcp/dist/index.js"],
      "env": {
        "MAIL_USER": "you@example.com",
        "MAIL_PASSWORD": "${MAIL_PASSWORD}",
        "IMAP_HOST": "imap.example.com",
        "SMTP_HOST": "smtp.example.com"
      }
    }
  }
}
  • MAIL_USER — the address you sign in with. For iCloud and some company servers this is only the part before @; then add MAIL_FROM with the full address.
  • MAIL_PASSWORD — the app-specific password from step 1.
  • IMAP_HOST / SMTP_HOST — optional for a known provider, required for anything else. Your provider calls them the incoming and outgoing mail server.
Do not commit a real password. Writing "${MAIL_PASSWORD}" as above keeps the file shareable: Claude Code and Cursor substitute environment variables, so the secret stays in your shell.

Open Settings → Developer → Edit config, which opens claude_desktop_config.json, and add: 

{
  "mcpServers": {
    "mail": {
      "command": "node",
      "args": ["/absolute/path/mail-mcp/dist/index.js"],
      "env": {
        "MAIL_USER": "you@fastmail.com",
        "MAIL_PASSWORD": "your-app-password"
      }
    }
  }
}

Save the file and restart the app completely (quit, not just close the window).

Create .cursor/mcp.json in your project with the same shape:

{

Add guard rails (optional, but read this one)

A mailbox password opens the whole mailbox. These three settings narrow what the assistant may do with it, and they are enforced by the server rather than by asking nicely in a prompt.

MAIL_READ_ONLYfalsetrue — the assistant can read everything and change nothing

The full list, including timeouts and size caps, is in .env.example and the README.

Verify

Check that it works

Ask your assistant this, exactly:

Run mail_whoamimail_whoami

A working setup logs in to both servers and answers with your address, the two host names, how many folders you have, how much of the inbox is unread, and your quota. It checks incoming and outgoing separately on purpose: a mailbox that reads perfectly can still be unable to send, and this tells you which half is broken.

If it reports that the credentials were rejected, the message names your provider and what it wants — nearly always an app-specific password where an account password was given. If the assistant says it has no such tool, the connection was not registered: check the path to dist/index.js, and restart the app.

Three things worth knowing

  • Reading does not mark as read. The assistant can go through your inbox and leave it exactly as it found it. Marking happens only when you ask for it.
  • Folder names are forgiving. Say "sent", "trash" or "archive" and the right folder is found, whatever your provider calls it — [Gmail]/Sent Mail, Отправленные or anything else.
  • Dates are forgiving too. "Since yesterday", "the last 7 days" and 2026-08-01 all work.

The interesting part

Attachments — actually opened, not just listed

An attachment lives inside the message as an encoded block, reachable only over an authenticated connection. An assistant without this server sees, at best, a filename. This one downloads the part and hands it over in the form that is actually useful.

Images

Looked at

PNG, JPEG, GIF and WebP come back as images. "What does this screenshot show?" is a question your assistant can now answer.

Text

Read

Logs, CSV, JSON, XML — handed over as text, decoded from whatever charset the sender used, including the legacy ones.

Everything else

Passed through

PDFs, spreadsheets and archives arrive intact as files the assistant can work with rather than links it cannot follow.

What it looks like

mail_read_message returns the body together with an attachment list — name, type, size, and the handle used to fetch each one: 

// mail_read_message → excerpt of the response
{
  "subject": "Q3 invoice and the screenshot",
  "from": "Anna Petrova <anna@partner.example>",
  "body": "Hi,\n\nInvoice attached, plus the screenshot…",
  "attachments": [
    { "part": "2", "filename": "invoice.pdf", "content_type": "application/pdf", "size": 48213, "inline": false },
    { "part": "3", "filename": "error.png",   "content_type": "image/png",       "size": 92104, "inline": false }
  ]
}

In practice you say "show me the screenshot" and both steps happen by themselves. The signature logos embedded in a message are marked inline, so they are never mistaken for the document you meant.

Only what is needed is downloaded. Reading a message fetches its body part alone — a message carrying a 20 MB attachment still costs a few kilobytes to read, and the attachment travels only when you ask for it. Anything above 8 MB is refused by default rather than pulled into the conversation.

Safety

Keeping it inside bounds

Email is not a read-only API with a scoped token. A mailbox password opens everything in the mailbox and can send as you. That deserves an honest answer rather than reassurance, so here is exactly what limits it.

A recipient allowlist

MAIL_ALLOWED_RECIPIENTS=@yourcompany.com — mail can only be addressed to those. To, Cc and Bcc are checked together, before the message reaches the outgoing server. The one setting worth having even when everything else is open.

Read-only

MAIL_READ_ONLY=true refuses every tool that would send, move, flag or delete. Searching and reading keep working completely.

A folder allowlist

MAIL_ALLOWED_FOLDERS=INBOX puts everything else out of reach, for reading as well as writing. Subfolders of a listed folder come along.

What is careful by default

Reading a messageLeaves it unread. Marking as read is a separate, explicit request
DeletingMoves to Trash. Erasing for good needs permanent and confirm together
Deleting a folderNeeds an explicit confirmation, because it takes every message in it along
The From addressFixed by your configuration. No tool argument can change who the mail appears to be from
Bulk markingCapped at 500 messages per call, so an over-broad search cannot quietly sweep the whole mailbox
Sent mailFiled in Sent as the exact bytes that were sent, so your own record matches what the recipient got

Where your password lives

  • On your machine. In the recommended setup the server runs locally and talks to exactly two parties: your assistant and your mail server. Nothing passes through anyone else.
  • Nothing is stored by this software. No database, no cache of your messages, nothing written to disk. Connections are held open briefly so repeated requests do not re-authenticate, and that is all.
  • Revoking is instant. Delete the app-specific password in your provider's settings and the access is gone, with no effect on your account.
  • Least privilege still applies. An app password that only permits IMAP and SMTP cannot be used to log in to the web interface or change your account.
  • What the assistant reads becomes part of your conversation with it, exactly as if you had pasted it in yourself. That is worth remembering before pointing it at a mailbox full of things you would not paste.

FAQ

Questions people actually ask

Which mail providers does this work with?

Any server that speaks IMAP, which is nearly all of them. Gmail, Outlook, Yahoo, iCloud, Fastmail, Zoho, Yandex, Mail.ru, GMX, AOL, Migadu and mailbox.org have presets, so your address alone is enough. For anything else — a company server, a small host, your own — you give the incoming and outgoing host names once.

Why does my password not work?

Because almost every provider refuses the account password over IMAP. You need an app-specific password: a separate value generated in the provider's security settings, used only here, revocable on its own. Gmail requires 2-Step Verification before the option even appears, and several providers additionally need IMAP switched on in the web interface. The error message from mail_whoami names your provider's particular requirement.

Can the assistant email anyone it likes?

Not if you set a recipient allowlist. MAIL_ALLOWED_RECIPIENTS restricts outgoing mail to named addresses or whole domains, checked across To, Cc and Bcc before anything reaches the outgoing server. There is also a full read-only mode in which nothing can be sent or changed at all.

Will it mark things as read, or move things around by accident?

Reading leaves a message unread unless you explicitly ask to mark it. Deleting means moving to Trash; erasing for good needs permanent and confirm together, and deleting a folder needs a confirmation of its own.

Does my password leave my machine?

Not in the setup documented above. The server runs locally and talks to exactly two parties: your assistant and your mail server. A hosted endpoint also exists for convenience, and there the password does pass through the host — which is precisely why the local mode is the one described first.

Can it read a screenshot someone emailed me?

Yes, and that is the difference between this and a text dump of your inbox. PNG, JPEG, GIF and WebP are handed over as images the model can look at; text files arrive as text, decoded from whatever charset the sender used; anything else arrives as a file it can still work with.

Will replies thread properly?

Yes. A reply carries the In-Reply-To and References headers from the original, so it appears inside the conversation in the recipient's mail client rather than starting a new one. The original is marked as answered, as any mail client would, and your copy is filed in Sent.

Can I connect two mailboxes at once?

Yes. Add two entries with different names — for example mail-work and mail-personal. The assistant sees both sets of tools and picks by name.

My company mail server is only reachable inside the network.

Then run the server locally, which is the recommended mode anyway: it connects from your machine, so anything your machine can reach works — a server on a private network, or a Proton Bridge listening on localhost.

What happens with a very large mailbox?

Nothing is downloaded wholesale. Searching runs on the server's own index, listings return short summaries, and reading a message fetches only its body part. Logging in is the expensive step, so authenticated connections are kept warm for a few minutes and reused instead of re-established for every request.

Troubleshooting

When something does not work

What you seeWhat it means and what to do
IMAP rejected the credentialsNearly always an account password where an app-specific one is required, or IMAP not yet enabled in the provider's web interface. The message names your provider's requirement
Cannot reach the SMTP serverOutgoing mail is port 587 with STARTTLS or 465 with TLS. Port 25 is blocked by most networks and providers
Mail reads fine but sending failsIncoming and outgoing are separate services. mail_whoami checks them separately and tells you which one is refusing
The connection hangs, then times outA TLS port configured as STARTTLS, or the reverse. For a non-standard port set IMAP_SECURE / SMTP_SECURE explicitly
The server refused the message (550)The account is not allowed to send as the configured From address. Set MAIL_FROM to an address it may use
No folder X in this accountThe error lists the real names. Providers localise them, and Gmail nests everything under [Gmail] — or just say "sent", "trash", "archive" and let it resolve
No message with UID NUIDs belong to one folder. A message that has been moved has a different UID in its new home
The assistant has no mail toolsThe connection was not registered. Check the path to dist/index.js, make sure npm run build ran, and restart the app completely

Hosted mode

Running it as a service

The same server also speaks HTTP, serving this page on / and an MCP endpoint on /mcp where every request carries its own mailbox credentials. One deployment then serves many mailboxes without holding any state. 

claude mcp add --transport http mail \
  https://mail-mcp.webapace.ink/mcp \
  --header "X-Mail-User: you@fastmail.com" \
  --header "X-Mail-Password: your-app-password"

Every environment variable has a header equivalent — X-Mail-Imap-Host, X-Mail-Smtp-Host, X-Mail-Read-Only, X-Mail-Allowed-Recipients and the rest; Authorization: Basic works instead of the two credential headers. The full list is in the README.

Understand the trade before using it. Your mailbox password passes through the host on every request. The service keeps nothing — no accounts, no database, nothing on disk, one throwaway server instance per request — but a mailbox password is not a scoped token, and no storage policy changes that. For mail, the local setup at the top of this page is the better default, and it is not harder.

Your own container

docker build -t mail-mcp . and it serves the same page and endpoint at your own address. Credentials stay inside your network, and MAIL_ALLOWED_HOSTS can pin it to your own mail servers.

Private networks are refused

Without an explicit allowlist a hosted deployment will not connect to localhost or private address ranges, so it cannot be used to probe the network it runs in. Reaching an internal mail server is a job for a local install.
